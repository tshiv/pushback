# Changelog

All notable changes to `pushback` are documented here. Format based on
[Keep a Changelog](https://keepachangelog.com/); versioning is [SemVer](https://semver.org/).

## [0.2.0] - 2026-11-06

### Added
- **A test suite, run in CI.** `test/run.sh` drives the real script end to end, 86 scenarios, against stubbed `xcodebuild`, `xcrun simctl`, `gh`, `xcodegen` and `maestro` and a throwaway local git remote, on the bash 3.2 at `/bin/bash`. It covers both modes, worktrees, fork PRs, every failure point around the upload, signals (including a real pseudo-terminal being closed or Ctrl-C'd mid-archive), the lock, the simulator lifecycle, and each fix below. CI runs it on macOS for every PR, next to ShellCheck.
- **`pushback doctor`** checks everything a ship depends on and lists every problem, not just the first: the toolchain, Xcode selection, `gh` sign-in, the App Store Connect key, `project.yml`, the bump script, `ExportOptions.plist`, the QA simulator, origin, the build number, leftover unpushed bump branches, and the ship lock. It changes nothing (apart from a `git fetch`).
- **A per-clone record of burned build numbers.** From the first upload attempt on, the build number is written to `.git/pushback.burned` (shared by every worktree, one line per app's `project.yml`, so two apps in one repo don't block each other; `ios`, `ios/` and `./ios` count as the same app). A later ship of that app from that clone refuses to bump to it again, however the kept bump went missing: stashed, discarded, reset, or on a deleted branch. Previously a kept bump that was stashed (`s` at the dirty-tree prompt) or thrown away let the next ship reuse the burned number.
- **`--dirty include|stash|abort`** decides a dirty tree without the menu. With `--yes`, unattended runs can now stash instead of only including everything or failing.
- **Preflight now checks, in seconds and before any build or merge:** that `ExportOptions.plist` sets `destination=upload`, and that the bump script exists and is executable. With any other destination the export wrote an IPA, exited 0, uploaded nothing, and pushback reported "Shipped" and committed the bump. A missing bump script was only found after the PR had been merged.
- The banner names the QA simulator it will use.
- **The QA simulator is shut down after the gate.** Previously the sim that `xcodebuild test` and Maestro used stayed booted after every ship, holding a couple of GB of RAM plus its background processes until you noticed. pushback now boots the sim itself when it isn't already running, and shuts it down as soon as the QA step ends, on success, on failure, and from the EXIT trap (Ctrl-C included). A sim that was already booted when the ship started is left running, since it belongs to you or another session. `PUSHBACK_KEEP_SIM=1` opts out.
- **One ship per repo at a time.** A lock in the repo's common git dir (shared by every worktree) stops a second concurrent `pushback`, which would otherwise bump to the same build number and fail App Store Connect validation after a full archive, and fight the first over the QA simulator. The message names the running pid and checkout; a lock left by a SIGKILLed run is taken over. A lock that has no owner yet but is under a minute old belongs to a run that is starting up, and is respected. A stale lock is renamed aside and checked rather than deleted in place, so two runs taking it over at once can't both win.
- **Stale build numbers are refused before any work.** Build numbers are global to the app, so pushback now compares the tree's build with `main`, `origin/main` and the target branch, and stops if any is ahead. This catches the worktree-cut-from-`origin/main` case where local `main` holds an unpushed bump from an earlier ship. From-main checks before the build. PR mode checks `origin/main`'s build, and that local `main` can fast-forward, before merging (the merge can't be undone), then rechecks after syncing.
- **A detached ship's bump commit is never orphaned.** When shipping a PR from a worktree (detached `origin/main`), the bump commit is put on `pushback-unpushed-bump-<build>` before the push and the branch is removed once the push lands. If the push is rejected, the burned build stays on that branch and the stale-build check scans those branches, so a later ship can't reuse the number. Running pushback from that branch is refused with the push it actually needs, instead of shipping again to a new remote branch of that name. (The name is flat, not `pushback/...`, so an existing branch called `pushback` can't block it. Branches under the 0.1.x-era `pushback/unpushed-bump-*` spelling are still checked.)

### Fixed
- **PR mode works from a git worktree.** After the merge, pushback ran `git checkout main`, which git refuses when `main` is checked out in another worktree, so the PR was merged and nothing shipped. pushback now fetches `origin/main` and, if `main` lives in another worktree, ships from a detached `origin/main` and pushes the bump with `HEAD:main`. Otherwise it checks out `main` and fast-forwards it; a diverged local `main` stops the run with the PR already merged and nothing bumped, instead of being silently merged by `git pull`. `gh pr merge` no longer gets `--delete-branch` (it switches the local checkout to `main` first, which fails the same way); pushback deletes the remote branch itself, but only for a same-repo PR (a fork's head branch is often named `main`, which must never be deleted on origin), never `main` or the target branch, and only while it still points at the verified PR head (`--force-with-lease`). The local branch is deleted only when it still points at that head too.
- **A failed upload no longer reverts the build number.** If `-exportArchive` exits non-zero after App Store Connect already accepted the binary (a dropped connection while waiting for the verdict), the bump used to be reverted and the next ship reused a burned number. The bump is now kept from the first upload attempt on, with the commands to commit and push it.
- The version bump is pushed as `HEAD:refs/heads/<branch>`, and the failure hints say the same, so recovery commands work from a detached checkout.
- From-main mode on a detached HEAD now fails up front instead of after the upload, when there would be no branch to push the bump to.
- The behind-upstream warning only runs in from-main mode. In PR mode it compared the PR branch with `origin/main` and warned about a gap the sync step closes anyway.
- **A terminal closed mid-ship no longer leaves the bump, the stash or the lock behind.** Three things went wrong in turn. On SIGTERM or SIGHUP, bash 3.2 runs the EXIT trap with `$?` still holding the last command's status, usually 0, so the cleanup took the killed run for a success. Once that was fixed, the cleanup's first message to the dead terminal failed (EIO) and `set -e` ended the cleanup there. And bash keeps the bytes it couldn't write buffered and flushes them into the next `$(...)` that prints, so the cleanup read its own messages back as the lock owner and the stash entry, and left both. INT, TERM, HUP and PIPE now exit 130, 143, 129 and 141; the cleanup runs with `set +e` and signals ignored (so a second Ctrl-C can't cut it short either), checks whether the terminal is still there before writing, and releases the lock and lets signals through again before the simulator shutdown, the one step that can hang.
- **Ctrl-C stops xcodebuild too.** Without xcbeautify, the build ran as a background job behind the spinner, and a non-interactive bash starts those with SIGINT ignored: pushback exited and reverted while the archive kept running into `build/`. The command now runs in the foreground and the spinner in the background.
- **A signed-out or offline `gh` no longer ships a PR branch as from-main.** A failed `gh pr view` looked the same as "no PR", so the branch's unmerged code was uploaded and the bump pushed to the PR branch. pushback now tells the two apart and stops when gh fails.
- Include mode can't commit `build/`: pushback's own artifacts are removed right after the upload, before `git add -A`, so a repo that doesn't ignore `build/` no longer commits the `.xcarchive`. Only what pushback created is removed (the final sweep used to delete `build/` wholesale), so files a repo tracks there survive.
- **A bump script that doesn't raise the build stops the ship before the archive.** A no-op or broken bump script used to archive and upload the same, already-shipped build number again, then fail at the commit. The build must now go up, and past this clone's burned record.
- A revert restores each commit path on its own. One path missing from HEAD (a gitignored, generated `.xcodeproj`) made the combined `git checkout` restore nothing, leaving the bump in the tree.
- A lock held by a process pushback may not signal (another user's) counts as live instead of stale, and a run only removes a lock it owns.
- **`.env.local` is parsed, not evaluated.** The App Store Connect variables were loaded with `eval`, so a value containing `$(...)` or backticks ran as a command. Lines are now read as `KEY=value` data (quotes and trailing comments handled, also together), and a variable already exported wins over the file.
- **Offline runs say so.** One `git fetch` up front replaces the three scattered pre-merge ones, which failed silently. When origin is unreachable, PR mode stops before doing anything (it can't merge or sync anyway), and from-main warns that remote branches are compared as last fetched. Previously an offline run could report a stale local view as "local main has diverged".
- The kept-bump hint after a failed upload commits everything (`git add -A`) in include mode, matching what was shipped, and names the real version in the commit message.
- Paths with spaces work: the default commit paths are built as an array (`My App.xcodeproj`), and `PUSHBACK_COMMIT_PATHS` may be a bash array. A plain string is still split on whitespace.
- Missing App Store Connect variables give pushback's own message instead of a raw bash `parameter not set` error.
- The stale-build message before a PR merge names `origin/main` rather than "this tree", and the push-failure hint gives the cleanup commands for the bump branch rather than "delete it once pushed" while it was still checked out.
- A missing `.git/pushback.lock/owner` (or burned record) no longer prints a stray "No such file or directory".
- A `PR_NUMBER` argument must be a number or a PR URL; anything else exits 2 instead of being handed to `gh`. `--dirty` or `--config` without a value exits 2 with a message (it used to exit 1 silently).
- A `project.yml` without `MARKETING_VERSION` or `CURRENT_PROJECT_VERSION` is reported as such, by a ship and by `doctor`, instead of ending the run with no message.

### Changed
- **`PUSHBACK_SIM_DEVICE` names are resolved to one UDID up front**, and every QA call (xcodebuild, `simctl install`, `maestro --device`) targets that UDID. A name must now match a device exactly; when several runtimes have a device of that name, the newest iOS runtime wins. This removes the last use of the ambient `booted` target, so a name config no longer flakes when two sims are up, and a stale UDID (Xcode updates delete simulators) fails before the build with a pointer to `xcrun simctl list devices available` instead of deep inside `xcodebuild test`.
- **The default simulator is the newest iOS runtime's first iPhone**, picked when `PUSHBACK_SIM_DEVICE` is unset. The old default, `iPhone 17`, has to match a device name exactly since names are resolved up front, and failed on any Mac without a simulator of exactly that name (for example one with only 17 Pro, 17e and Air after an Xcode update). Runtimes compare as versions (18.10 after 18.2). Pinning a dedicated simulator's UDID is still the recommendation.

## [0.1.1] - 2026-09-05

### Fixed
- **A failed or rehearsed ship no longer discards your own uncommitted `project.yml` edits.** In from-main mode with the `include` choice, the revert after a pre-upload failure (and at the end of every `--dry-run`) ran `git checkout --` on the commit paths, which reset `project.yml` and the `.xcodeproj` to HEAD and silently threw away whatever edits you had there. pushback now snapshots your state of those paths right after the dirty-tree decision and restores to that snapshot instead of to HEAD. Staged and unstaged edits are both preserved as content (the staged split is not, since include mode stages everything anyway). If the patch can't be re-applied it is kept at `<repo>/pushback-preship.patch` with the exact command to apply it. Stash mode and clean trees behave exactly as before.
- **The pre-ship stash is restored by commit SHA, not by stack position.** `git stash pop` takes whatever is on top of the stash stack, and that stack is shared across every worktree of the repo. Another session pushing a stash during the multi-minute archive meant pushback popped the wrong entry and left its own behind. The stash is now pushed with a unique message, its SHA recorded, and restored with `stash apply <sha>` followed by a drop of that specific entry. The recovery hint on a conflict names the SHA.

### Changed
- Removed em dashes from all user-facing output and docs. No behavior change.
- **The archive step no longer leaks DerivedData outside the repo.** `xcodebuild archive` was the one invocation without a `-derivedDataPath`, so it fell back to `~/Library/Developer/Xcode/DerivedData/<Project>-<hash>`, where the hash is derived from the `.xcodeproj` *absolute path*. Shipping from a git worktree therefore minted a separate 2 to 3 GB cache for every worktree path, and Xcode never reclaims those when the worktree is deleted, so they accumulate silently: the leak was found at 15 orphaned directories totaling ~30 GB against 7 live worktrees. The archive now builds into `<app dir>/build/archive`, which is worktree-local and removed right after the upload.

  *Tradeoff, so this isn't mistaken for a regression later:* `build/` is wiped at the end of every successful ship, so the release archive is now always a cold build. Previously the default-location cache persisted, so a second ship from the same path reused it. This is a deliberate trade. Under a worktree-per-feature workflow most ships start from a fresh worktree where there was no cache to reuse anyway, and a hermetic release archive is worth having on its own merits. If the wall-clock cost does start to bite, the escape hatch is to stop deleting `build/archive` after the upload and exclude it from the final `build/` sweep: that leaves one warm cache per live worktree, still dying with the worktree, bounded by worktree count instead of unbounded.
- **`PUSHBACK_SIM_DEVICE` now accepts a UDID**, not just a name. A bare name is a prefix match (`iPhone 17` also resolves `iPhone 17 Pro`/`Pro Max`/`17e`, and duplicate names exist across OS runtimes), so with several matches, or two booted sims, `simctl install booted` and a device-less `maestro test` picked a device nondeterministically and flaked the QA gate. When the value is UDID-shaped it is now threaded into xcodebuild (`-destination id=`), `simctl install <udid>`, and `maestro --device <udid>`. Plain names keep the previous behavior.

## [0.1.0] - 2026-06-19

Initial release. Extracted from the `ios/ship.sh` tooling in a private app repo.

### Added
- One-command iOS TestFlight ship: verify → QA gate → (merge PR) → bump → archive → upload → commit & push.
- **Two auto-detected modes**: PR mode (open PR for the branch, or a PR number) and from-main mode (ship the current branch's state).
- **Dirty-tree handling** in from-main mode: include uncommitted changes in the bump commit, stash and ship committed HEAD only, or abort.
- Pre-ship summary + confirmation in both modes (`--yes` to skip).
- `--dry-run` that stubs the merge/archive/upload/push and reverts the bump.
- Terminal UI: banner, numbered step counters with per-step timing, `xcbeautify` streaming (spinner fallback), `NO_COLOR`/non-TTY safe.
- Config via a sourced `.pushbackrc` shell file (no YAML dependency).
- Burned-build-number safety: a bump is never reverted once the upload has succeeded.
